Reducing false positives without lowering the bar

Mukesh Kumar, CAMS · Operations · November 2026

Every monitoring team wants fewer false positives. The risk is that "fewer alerts" quietly becomes the goal and the system stops seeing what it was built to see. When I led a transaction monitoring team, the reduction we achieved came from better decisions, not from switching rules off.

Fix the decision before the rule

Inconsistent dispositions create noise of their own. If two analysts close the same pattern differently, any tuning built on that history inherits the inconsistency. The first step was a shared standard for a good investigation, supported by QA sampling and feedback analysts could act on the same week.

Let the evidence choose the rules to tune

Once dispositions were reliable, closed-alert data showed which scenarios produced little of value and why: thresholds set without regard to customer segment, rules firing on activity already explained by the customer's profile, and duplicate alerts for the same underlying behaviour. Each has a specific fix, and each fix can be written down with its rationale.

Keep the bar where it is

  • Test tuning changes against historical true positives before deploying them. If a change would have missed a filed SAR or STR, it does not go live.
  • Route the highest-risk alerts first so queue pressure never forces rushed decisions on the cases that matter.
  • Track quality, turnaround and productivity together. Improving one at the expense of the others is not an improvement.

The goal is a monitoring programme where analysts spend their time on alerts that deserve it, and where every tuning decision could be explained to an auditor or regulator from the record alone.
